# 計算・実験の記録

計算・実験・シミュレーションごとに `experiments/<名前>/` を作り、データ、図、解析のスクリプト、記録の README をまとめて置く。

| ディレクトリ | 内容 |
| --- | --- |
| [template](template/README.md) | 新しく作るときにコピーするひな形 |

## 新しく作る

```sh
cp -r experiments/template experiments/<名前>
```

`<名前>` は、あとで見て何かわかる短い英数字にする（例: `xrd-sample1`、`fe-scf`）。関連するものはまとめてよい（例: 練習のものは `experiments/tutorial/<名前>/`）。

## 中の構成

```text
experiments/<名前>/
├── README.md   目的・条件・結果の記録
├── data/       生データ（計算の出力、測定データ）。手で書き換えない
├── fig/        図
└── tools/      解析や図を作るスクリプト
```

分野に合わせて変えてよい。例:

| 研究の種類 | 構成の例 |
| --- | --- |
| 第一原理計算など、計算サーバで回す計算 | サーバの作業ディレクトリと同じ構成にする（例: 入力 `in/`、出力 `out/`）。入出力をサーバからコピーしてくる |
| 実験・測定 | 装置から出てきたファイルは `data/` にそのまま置き、補正や換算をしたものは `tools/` のスクリプトで別のファイルに出す |
| シミュレーション・機械学習 | 条件のファイルを `in/` や `configs/` に置き、条件ごとに出力を分ける |

- **生データは書き換えない。** 補正・換算・平均などは `tools/` のスクリプトで行い、結果は別のファイルや `fig/` に出す。どのデータからどの図ができたかを、あとからたどれるようにするため。
- **大きいファイルやバイナリは git で追跡しない。** [.gitignore](../.gitignore) にパターンを足し、置き場所（研究室のサーバのパスなど）を README に書いておく。小さいテキストのデータは、記録として追跡しておく。
- **`tools/` のスクリプトは使い回せる形にする。** 読み込みと描画を関数に分け、入出力のパスを引数で受け取るようにしておくと、次の計算・実験のデータにもそのまま使える。複数で使うものは、それらをまとめたディレクトリの直下の `tools/` に置く。
- **README に記録する。** 実行・測定の日付、目的、条件、結果（うまくいったか、主な数値、図）を書く。コミットメッセージの本文にも主な結果を書いておく（`exp(<名前>): ...`）。
